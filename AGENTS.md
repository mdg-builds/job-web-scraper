# Front-End Job Scraper

Front-End Job Scraper is a portfolio piece for GitHub — hiring managers will read the repo as if a human wrote every line. Build it in plain Python, kept as simple as possible. **Python only** — no Node, React, or other frontend frameworks for the shipped app.

## What it does

A Flask website that scrapes job listings aimed at front-end developers. Users pick a preset target or paste a custom listing URL, set a **days posted** filter (e.g. last 1 / 3 / 7 / 14 / 30 days), and see matching roles on the page: title, company, location, posted date, link, and tags when available.

Results stay on-page only (no CSV/JSON download). Empty and error states must fail clearly — timeouts, bad URLs, parse failures, or no matches after filtering — without crashing.

## Current state

A working Flask website:

- `scraper.py` — fetch/parse/normalize listings, days-posted filter, presets (RemoteOK JSON, Remotive API, WWR RSS) plus custom HTML/RSS/JSON.
- `app.py` — Flask routes: `/` (form + results), `/demo/board` (local sample board for custom-URL demos).
- `templates/` — Jinja2 templates (`base.html`, `index.html`, `demo_board.html`).
- `static/style.css` — the site's stylesheet.

Run it with `pip install -r requirements.txt && python3 app.py`, then open http://127.0.0.1:5000.

## Stack constraints

- Plain Python + Flask + Jinja2 + CSS.
- Scraping via common libraries in `requirements.txt` (e.g. `requests`, BeautifulSoup; `python-dateutil` only if needed for posted dates).
- No JavaScript frameworks. Minimal JS only if a tiny UX aid is truly necessary.
- Keep `requirements.txt` as the only dependency source.

## UI bar (interviewers will judge this)

The UI is part of the portfolio. It should feel intentional and polished, not a default Bootstrap form.

- One strong first viewport: product name as a hero-level signal, one headline, one short supporting line, and the scrape CTA. Avoid dashboard clutter.
- Expressive typography and an atmospheric background (gradients, subtle pattern, or texture) — not a flat gray page and not generic “AI purple” defaults.
- Results that scan well: clear hierarchy for title / company / location / date / link. Prefer a focused list or result cards over widget strips and stat rows.
- Empty, loading, and error states that look designed, not like raw Flask debug text.
- Prefer CSS for motion (subtle enter / result reveal). Keep any JS minimal.
- Works cleanly on desktop and mobile.

## Portfolio rules (non-negotiable)

- Clean, organized, simple Python. Prefer small functions and clear names over cleverness.
- **Never commit AI artifacts.** Keep `CLAUDE.md`, `.cursor/`, agent transcripts, and similar out of git. If adding a `.gitignore`, exclude them plus `venv/`, `__pycache__/`, `*.pyc`.
- Do not leave AI fingerprints: no "Generated by…", no filler comments, no over-engineered abstractions, no unused helpers.
- README is the public face. Keep it accurate and human. Do not mention Claude/Cursor/AI in committed files.
- Every feature that already exists must keep working after a change. Do not ship half-broken UI.
- Prefer extracting modules over growing `app.py` or a single `main.py`.
- Validate inputs (URL, filter values) and fail clearly; do not crash on bad or unreachable pages.
- Respect scrape ethics: polite timeouts, honest User-Agent, no hammering targets. Document preset sources and limitations in the README.
